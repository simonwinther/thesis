**Verdict: sound skeleton, but it cannot yet answer the question it exists for.** The arithmetic and conventions are right. As written, though, the likeliest outcome is "inconclusive", the go-rule compares the wrong pair, and the HF metric can pass while interior detail is lost. Nothing was edited or run, and I did not open `review-v1.json`, to stay independent.

**Confirmed against local code**
- **Conventions:** band order and `LLL/3`, `×3` match `wfm.py:35,42`; pad and crop match `bratsloader.py:48-50`; masked SSIM matches `evaluate.py:143-144`.
- **Compression:** 8,028,160 → 62,720 scalars is 128×, and 64× positions. Per branch it is LF 32× and HF **224×**; state that, since detail lives in the 224× branch.
- **Leakage:** none as designed, with VAEs fit on train only. I did not inspect the split manifests.

**Must-fix**

1. **2,500 updates is half an epoch** (1,251×4 = 5,004 scans). MSE training fits high-energy low frequencies first, so stopping early biases towards "HF lost", the very conclusion under test. Write the rule as one-sided: a good result means go; a poor result says nothing about the bottleneck. Set the cap from step 2's measured throughput and a stated wall-clock budget.

2. **Make the overfit step the capacity bound.** Memorising four scans is the best case for this bottleneck. Run it to plateau, not 300 updates, and require HF relative error clearly below 1. "Clear loss reduction" is not diagnostic for HF: an untrained decoder typically outputs values much larger than HF coefficients, so collapsing to zero already looks like progress. If HF stays near 1 at plateau, stop before the pilot.

3. **The go-rule compares the wrong pair.** Control (c) uses the *original* LF, so VAE-LF + VAE-HF can lose to it purely through LF error. Add one row, VAE-LF + zero HF. LF cost is then (c) versus that row; HF gain is that row versus the full VAE.

4. **Global HF relative error is dominated by the skull-strip boundary.** The brain/zero edge gives the largest Haar coefficients, so a model that draws only the outline scores well. Also report HF relative error over positions whose 2×2×2 block lies fully inside `target>0`. That is the detail number.

5. **Beta is mislabelled by convention.** With mean MSE and mean KL, the per-nat weight against SSE is β·N_out/N_lat: 3.2e-5 for LF and 2.2e-4 for HF. The MONAI/LDM tutorial convention, as I recall it, sums KL over the latent, which makes the same nominal 1e-6 about 31,000× stronger. Keep 1e-6 without a sweep, but write "near-autoencoder: best-case reconstruction, not evidence the latents suit WFM". Log per-channel mu mean/std and mean sigma.

6. **Name the MONAI calls.** From memory of MONAI ≥1.4, which I could not inspect here:
   - `forward()` and `encode_stage_2_inputs()` always sample, even in eval mode.
   - `encode()` returns `(mu, sigma)`, a std rather than a logvar.
   - Validation and any future cache must use `encode()` then `decode(mu)`.
   - The older `monai-generative` package calls the argument `num_channels`.
   - Assert encoder output `[1,2,28,28,20]` in `checks.py`.

**Should-fix**
- **DWT test shapes:** `DWT_3D.get_matrix` sizes its matrices from the last two dims only (`DWT_IDWT_layer.py:465`) and moves them to CUDA whenever it is available (`:505`). Test tensors need first spatial dim ≤ max of the other two, and "CPU checks" on a GPU node need CUDA hidden.
- **Precision:** "KL in float32" implies AMP. HF targets are small, so compute MSE in float32 too, or skip AMP.
- **SSIM/PSNR:** expect them to move little when HF is dropped; control (c) will show this. The detail verdict should rest on interior HF error and the zoom panel.
- **Anchor instead of "no cutoff":** reconstruction must clearly beat the current WFM *synthesis* scores on the same cases, or latent WFM is capped below the baseline. `evaluate.py:22` clips negatives on load, so match that or flag the difference. I did not inspect the baseline result files.
- **Speedup wording:** 28×28×20 halves cleanly only twice (to 7×7×5), so a latent WFM backbone probably cannot reuse the current depth, and decoding still runs at inference. I did not inspect the current U-Net config.

**Reject or drop**
- **Statistics at n=8:** drop median, 10th percentile, SD and distribution plots; a per-modality mean and min table is enough.
- **Extra panels:** defer lowest-SSIM cases and three orientations.
- **Full-219 evaluation in this pilot:** keep that set for reporting only, and never select a checkpoint or beta on it.
- **Correctly excluded already:** sampled-z evaluation, perceptual/GAN losses, coefficient standardisation, beta or channel variants, extra seeds, lesion metrics.
- **Keep unchanged:** `channels=(32,64,64)`, one res block, Adam 1e-4, batch 1, seed 43. These are arbitrary but standard, and the overfit step shows whether capacity is the limit.
