## 4. Implementation checks

- **Source flags:**
  - Learned jobs get `--source learned --source_init {uniform|random}`; Mean and Gaussian get `--source mean|gaussian` (`run_one.py:62-63`).
  - MLP8 sets `use_statistics=False`. In `source.py:167-171` this keeps only the last 8 input columns of the first layer (4 availability + 4 target flags) after the same seeded initialisation. The 128/128 hidden layers, 32 outputs, prior and zeroed output layer are unchanged.
  - MLP72 has 72 inputs, with statistics computed on available inputs only (`masked_subband_stats`). Mean and Gaussian keep `use_statistics=True`, which they ignore.
  - The boolean flags are parsed correctly as true/false values.
- **Seed and noise:** training uses `--seed 43` (source init seed 44, Gaussian noise seed 45, unchanged); evaluation uses seed 42. The noise rule is still `sigma_max·sqrt(t(1−t))` (`wfm.py:98`) and `sigma_max` is passed directly. The `wfm.py` hash is identical to high-sigma.
- **Batch and target policy:**
  - BS1 uses a plain shuffled loader and one random target per update (`random.choice`).
  - BS4 uses `DistinctPatientBatchSampler` (four patients by patient ID, not scan ID) and a per-sample permutation of all four targets. `run_step` raises an error unless the batch has 4 distinct patients and the class labels match.
  - `check_training` re-checks every one of steps 1..N afterwards: 4 rows, 4 patients, 4 targets, and the other three modalities as conditions. BS1 is checked for batch 1, input shape [1, 32], and all four targets appearing.
- **Update count:** the training loop stops at `max_iterations`. There is no learning-rate schedule tied to the total length, so a 2500-step run is the same procedure as the first 2500 steps of a 10000-step run.
- **Checkpoint pairing:** `save()` writes `wfm_unified_N.pt` and `source_unified_N.pt` together. The sampler derives the source path from the model path (`sample_wfm.py:71-76`). `check_training` loads each source checkpoint and checks seed, architecture, `use_statistics`, mode/init, input width (72 or 8) and prior shape (4, 4, 8). No optimizer files are saved.
- **Train-then-evaluate:**
  - Evaluation runs largest step first (10000, then 2500).
  - Results that already pass validation are skipped. Validation requires all 4 targets, the exact 219 case IDs, and finite masked SSIM/PSNR.
  - A retry after training has finished goes straight to evaluation.
- **Recovery restrictions:** `train_wfm.py:121-123` refuses recovery unless the run is learned and mixed-target, so BS1 and Mean/Gaussian correctly use `recovery_interval=0`, and preflight enforces this mapping.
  - On restart, learned BS4 jobs restore their full state and trim `batch_targets.csv` and `progress.csv` back to the restored step, so the per-step audit never sees duplicate rows.
  - Interrupted BS1 and Mean/Gaussian runs are moved to `failed_attempts/` and restarted from scratch.
- **Code identity:** all 77 entries in `code_sha256.json` match the high-sigma manifest. The remote check reports that plan, code and runner hashes match on both hosts, and that 6169's actual running command matches the plan.
- **Slurm settings:** partition `gpu`, 1 GPU, 4 CPUs, 48 GB on all jobs. Hendrix uses the approved node-exclusion wrapper. Existing jobs (1383–1386, 5603–5606, 1782/1807) are still present.

## 5. Caveats (none of these block the runs)

- **Runtime:** for jobs that haven't started, finishing can't be guaranteed.
  - A Slurm timeout does not requeue the job, so a timed-out job needs manual resubmission.
  - Estimates from the high-sigma runs on A40s are about 3.1–3.2 h per 1000 BS4 updates: roughly 32 h for 10k (limit 48 h) and 8 h for 2500 (limit 12 h). That is enough but not generous.
  - BS1 jobs have a 12 h limit; I have no direct timing evidence for them on these hosts.
  - The Mostafa BS1 jobs won't start until the 4 running high-sigma jobs free their GPUs; Slurm currently estimates around 15 Nov.
- **Restarts:** Gaussian BS4/10k and all BS1 jobs restart from scratch if requeued. The `gpu` partition does not preempt, so this is unlikely.
- **Comparability:**
  1. For Mean and MLP72 at sigma 0/0.5, the BS4 2500 and 10000 results come from different runs (a new short run vs. the historical 10k run), not two snapshots of one run.
  2. The historical BS1 sigma 0/0.5 results for Mean, Gaussian and MLP72 came from the older B200/pilot runs. The new MLP8 BS1 results at those sigmas use current code on Mostafa/Hendrix GPUs, so hardware and software differ within those columns.
  3. Hendrix GPU type varies by allocation (A40, A100, L40S or H100).
  4. BS1 sees 10k examples and BS4 sees 40k, and only BS4 uses activation checkpointing.
  5. This is a single seed, so no significance can be claimed.
